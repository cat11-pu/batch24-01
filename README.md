# GSB Bugfix Task
## 题面
财务发现同一张优惠券被核销了两次，两个请求几乎同时到达，状态检查和使用之间没有锁，过期券、别人的券、超过使用上限的券也都放过去了。redeem 在 coupon_redeem.py，仓库里 15 条用例眼下全红。要求是：未使用的券只能成功一次，券要绑定用户和活动，过期、超限、未知券一律拒绝，两个请求同时核销只能有一个拿到成功。这 15 条过了之后，我会用 1000 组随机券状态、32 路并发再压一遍唯一性；用例和券号都不许改或写死。空券、空用户、未知券、过期、已用、跨用户、超限、并发这些场景都要考虑。

## 运行方式
```bash
python -m pytest tests -q
```
